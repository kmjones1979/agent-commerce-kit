# 90-second demo script

A screen-share that shows **one approval path** and **one denial path**, plus the
"secrets never leave the vault" story. Have the app running (`just start`) and
the Ampersend dashboard (app.ampersend.ai) open in a second tab.

> Recording: capture this run to `docs/demo.mp4` (≈30s for the pizza-approval
> flow). The repo ships the script; the `.mp4` is produced by recording your own
> screen — it is not generated by the kit.

---

**0:00 — The setup (10s)**
> "This is an onchain AI agent that can place real orders. Every payment goes
> through a policy layer, and every secret lives in a 1Claw HSM vault — not on
> disk, and never in the model's context."

Show the chat page. Point at the **status strip**: Ampersend connected, today's
**daily remaining**, the active **payment instrument (last-4 only)**.

**0:10 — Prove the vault story (15s)**
Open **/vault**. Scroll the list: green = populated, red = missing. 
> "These are vault *paths* — the page never reads a single value. The card number,
> the Ampersend key, the vendor keys — all in 1Claw."

Open **/audit** briefly: empty (or prior runs). 
> "Every order will land here: intent → approval → settlement."

**0:25 — Approval path (30s)**
Back to chat. Type: **"order me a pepperoni pizza."**
- The agent calls `order_pizza`. Narrate: "It quotes the price, then asks
  Ampersend to co-approve before any money moves."
- Switch to the **Ampersend app** → approve the prompt (or show the spend landing
  within limits).
> "Two keys signed — the agent's and Ampersend's. Neither can spend alone."
- Back to chat: the agent reports the order (dry-run preview by default, or a real
  order if `COMMERCE_*_LIVE` is on). The **status strip** shows a new transaction
  badge; **/audit** now has the row: approved → settled, instrument `••••NNNN`.

**0:55 — Denial path (25s)**
In the Ampersend dashboard, **lower the daily limit** below the next order amount.
Back to chat: **"send a $5 Amazon gift card to the demo recipient."**
- The policy layer pre-checks the limit and Ampersend declines the co-sign.
> "Over the daily limit — the agent gets a clean `PolicyDenied` and does **not**
> retry."
- Show the agent explaining the denial. **/audit** shows the row as `denied` with
  the reason.

**1:20 — Close (10s)**
> "Real vendor APIs, stablecoin-funded, every transaction policy-gated and
> audited — and the model never saw a key, a card number, or a vault value."

Show the status strip / audit one more time. Done.

---

## Quick denial reset

To re-run the denial demo, raise the Ampersend daily limit again in the
dashboard — the next order will pass. Limits are **read** by the kit and **set**
only in the dashboard (in your own browser).
